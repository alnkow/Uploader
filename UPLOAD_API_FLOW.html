Фронтенд загрузки данных · версия от 13.10.2026 · минимальная рабочая версия

API загрузки пакетов

Какие запросы отправляет браузер, когда пользователь загружает файлы: адрес, заголовки, тело, что фронтенд ждёт в ответ и куда кладёт данные из ответа. Пути и форматы — предложение фронтенда. Если у бэкенда удобнее по-другому, скажите, фронтенд подстроится.

API Обычные запросы

JSON-запросы к /api/batches. Авторизация — access-токен пользователя, как во всём приложении.

Tus Передача файлов

Протокол Tus 1.0: создать загрузку, отправить байты, при обрыве спросить смещение. Авторизация — upload-токен пакета.

Один домен

Всё идёт через nginx на 443, на тот же домен, что и приложение. CORS не нужен.

Весь путь на одной схеме

Пример: пакет «видео» из двух файлов. Цифры на стрелках — номера шагов ниже.

Шаги по порядку

0

Выбор файлов

запросов нет

Пользователь открыл форму, выбрал тип данных и перетащил файлы.

Что происходит

Всё проверяется в браузере, на сервер ничего не уходит:

  • формат — по расширению имени файла;
  • размер файла — до 25 ГиБ (26843545600 байт);
  • сумма файлов пакета — до 100 ГиБ (107374182400 байт).

ГиБ = 1024³ байт. Проверка в браузере нужна только для удобства, сервер проверяет то же самое сам.

1

Создать пакет

API · access-токен

Пользователь нажал «Загрузить». Один запрос на весь пакет.

Запрос
POST /api/batches
Authorization: Bearer <access-токен пользователя>
Content-Type: application/json

{
  "dataType": "video",
  "metadata": {},
  "files": [
    { "name": "flight_0412.mp4", "size": 21474836480 },
    { "name": "flight_0413.mp4", "size": 4294967296 }
  ]
}
  • files — только имена и размеры, без содержимого. Порядок важен: позиция файла в массиве — его номер fileIndex (0, 1, …).
  • metadata пока пустой: поля по типам данных добавим, когда аналитик даст их список.
Ответ
201 Created
Content-Type: application/json

{ "batchId": "7f3c9a2e" }
Куда кладём
  • batchId → очередь загрузок в памяти и метаданные каждого файла. Дальше он будет в адресах шагов 2, 7, 8 и в каждом Tus-запросе.
  • fileIndex → метаданные файла. Его выдаёт не сервер: это позиция файла в files.

Пакет встаёт в очередь. Одновременно загружается один пакет, остальные ждут.

Если ошибка

Любая ошибка: форма показывает «Не удалось начать загрузку», файлы остаются в форме, пользователь может нажать ещё раз. Сам фронтенд этот запрос не повторяет.

Бэкенду

Проверить метаданные и лимиты, сохранить манифест (список файлов в этом порядке). Тексты ошибок не должны упоминать внутренние контуры.

2

Получить upload-токен

API · access-токен

Очередь дошла до пакета, перед первым Tus-запросом. Повторно — после ответа 401 от Tus (шаг 6).

Запрос
POST /api/batches/7f3c9a2e/upload-token
Authorization: Bearer <access-токен пользователя>

Тела нет.

Ответ
200 OK
Content-Type: application/json

{ "token": "eyJhbGciOi…", "expiresAt": "2026-10-13T18:00:00Z" }
Куда кладём
  • token → только память вкладки, отдельно для каждого пакета. Не в localStorage. Подставляется в заголовок Authorization каждого Tus-запроса этого пакета.
  • expiresAt → не используем. Что токен устарел, фронтенд узнаёт по ответу 401.
Если ошибка

Tus-запрос без токена не уходит, это считается сбоем связи: повтор по общим правилам (таблица ниже).

Бэкенду

Зачем отдельный токен: загрузка 100 ГиБ может идти дольше сессии пользователя. Токен действует только для Tus-адреса и только для этого пакета, живёт часы. Можно запрашивать повторно. Отзывается после завершения или отмены пакета.

3

Создать загрузку файла

Tus · upload-токен

Для каждого файла пакета, до 4 файлов одновременно. Запрос только объявляет файл, байтов в нём нет.

Запрос
POST /api/uploads/                ← путь уточняется у бэкенда
Authorization: Bearer <upload-токен>
Tus-Resumable: 1.0.0
Upload-Length: 21474836480
Upload-Metadata: name ZmxpZ2h0XzA0MTIubXA0,type dmlkZW8vbXA0,batchId N2YzYzlhMmU=,fileIndex MA==,filetype dmlkZW8vbXA0,filename ZmxpZ2h0XzA0MTIubXA0

Upload-Metadata по правилам Tus: пары «ключ значение-в-base64» через запятую. В расшифрованном виде:

КлючЗначениеЧто это
batchId7f3c9a2eИз ответа шага 1
fileIndex0Позиция файла в files из шага 1. Приходит строкой
name, filenameflight_0412.mp4Имя файла. Два ключа с одним значением добавляет сам Uppy
type, filetypevideo/mp4Тип от браузера. Для .mbtiles, .rar, .z01 бывает пустым, доверять ему нельзя
Ответ
201 Created
Tus-Resumable: 1.0.0
Location: https://<домен приложения>/api/uploads/3b1e40c7
Куда кладём
  • Location → состояние файла в Uppy, только в памяти. Все следующие запросы по этому файлу (PATCH, HEAD, DELETE) идут на этот адрес.
Бэкенду
  • Проверить: токен выдан для этого batchId; fileIndex есть в манифесте и этот файл ещё не загружен целиком; Upload-Length совпадает с размером из манифеста. Метаданные присылает браузер, верить им без проверки нельзя.
  • Location — внешний адрес, через nginx и https (для tusd флаг -behind-proxy), или путь без домена.
4

Отправить содержимое

Tus · upload-токен

Сразу после шага 3.

Запрос
PATCH /api/uploads/3b1e40c7
Authorization: Bearer <upload-токен>
Tus-Resumable: 1.0.0
Upload-Offset: 0
Content-Type: application/offset+octet-stream

<байты файла с 0-го до конца>

Файл уходит одним запросом целиком, хоть 25 ГиБ: частями фронтенд не режет.

Ответ
204 No Content
Tus-Resumable: 1.0.0
Upload-Offset: 21474836480
Куда кладём
  • Upload-Offset равен размеру файла → файл загружен. Когда загружены все файлы пакета, переходим к шагу 7.

Прогресс на экране браузер считает сам, по отправленным байтам. Для него ответы сервера не нужны.

Бэкенду

Записывать данные на диск по мере поступления. Если связь оборвётся на 12 ГиБ, эти 12 ГиБ должны остаться на сервере. Поэтому в nginx для этого адреса: proxy_request_buffering off и client_max_body_size 0. С буферизацией nginx при обрыве ничего не передаст Tus-серверу, и загрузка начнётся с нуля.

5

После обрыва: узнать, сколько уже есть

Tus · upload-токен

Связь пропала или сервер ответил ошибкой. Tus-клиент сам повторяет через 0,1, 1, 3 и 5 секунд. Не помогло — фронтенд ждёт 10 секунд и начинает заново, и так без ограничения, пока не получится или пользователь не отменит пакет.

Запрос
HEAD /api/uploads/3b1e40c7
Authorization: Bearer <upload-токен>
Tus-Resumable: 1.0.0
Ответ
200 OK
Tus-Resumable: 1.0.0
Upload-Offset: 12884901888
Upload-Length: 21474836480
Cache-Control: no-store
Куда кладём
  • Upload-Offset → никуда не сохраняем, сразу используем: следующий PATCH уходит с Upload-Offset: 12884901888 и только с оставшимися байтами.

Сколько загружено, всегда знает сервер. Браузер не гадает, а спрашивает, поэтому продолжение точное.

Бэкенду
  • 404 или 410 на HEAD — только если загрузки правда нет (удалена или истекла). Получив такой ответ, фронтенд создаёт загрузку заново (шаг 3) и отправляет файл с нуля.
  • 401 и 5xx на HEAD фронтенд считает временными и переспрашивает. Другие 4xx Tus-клиент тоже понимает как «загрузки нет».
  • Смещение должно переживать перезапуск Tus-сервера.
6

Upload-токен устарел

TusAPI

Любой Tus-запрос получил 401.

Что делает фронтенд
  • Забывает старый токен → запрашивает новый (шаг 2) → повторяет тот же запрос с новым токеном.

Файл при этом не начинается заново: продолжение идёт с того же смещения.

Бэкенду

На просроченный или чужой токен отвечать именно 401. На 403 фронтенд не станет обновлять токен и покажет пользователю ошибку пакета.

7

Сообщить, что пакет загружен

API · access-токен

Все файлы пакета загружены целиком.

Запрос
POST /api/batches/7f3c9a2e/complete
Authorization: Bearer <access-токен пользователя>

Тела нет.

Ответ
202 Accepted

Подойдёт любой 2xx, тело фронтенд не читает.

Что делает фронтенд

Убирает пакет из списка загрузок, забывает его upload-токен и запускает следующий пакет из очереди.

Если ошибка

Сеть, 5xx, 408, 429 — повтор каждые 10 секунд, без ограничения. Другие 4xx — пакет показывается с ошибкой и кнопками «Повторить» и «Отменить».

Бэкенду
  • Повторный вызов безопасен: если ответ потерялся, фронтенд пришлёт запрос ещё раз. Уже завершённый пакет — снова 2xx, а не ошибка.
  • Если загружены не все файлы — 400 или 422. Не 409: 409 и 423 фронтенд считает временными и будет повторять бесконечно.
8

Отмена пакета

TusAPI

Пользователь нажал «Отменить» и подтвердил. Можно в любой момент: в очереди, во время загрузки, при ошибке.

Запросы
для каждого файла, загрузка которого начата, но не закончена (upload-токен):
DELETE /api/uploads/3b1e40c7
Authorization: Bearer <upload-токен>
Tus-Resumable: 1.0.0

для пакета целиком (access-токен):
DELETE /api/batches/7f3c9a2e
Authorization: Bearer <access-токен пользователя>

Запросы уходят почти одновременно. Ожидаемый ответ на оба — 204 No Content.

Что делает фронтенд

Сразу убирает пакет из списка, не дожидаясь ответов, и запускает следующий из очереди. Если запрос не прошёл, фронтенд его не повторяет.

Бэкенду

DELETE /api/batches/{batchId} сам удаляет все файлы пакета, и загруженные, и недогруженные, и отзывает upload-токен. На Tus-DELETE полагаться нельзя: он может не дойти или прийти уже после отзыва токена. Брошенные пакеты удаляются по сроку хранения.

Закрытие вкладки — запросов нет. Загрузка останавливается, уже загруженное остаётся на сервере до истечения срока хранения. Продолжение после повторного открытия будет позже, для него понадобится GET /api/batches.

Где фронтенд держит данные из ответов

Всё хранится только в памяти вкладки. В localStorage ничего не пишем: ни токены, ни адреса.

upload-токенОтвет шага 2Память UploadManagerAuthorization в Tus-запросах

Исключение — шаг 1: там любая ошибка просто показывается в форме.

Что нужно от бэкенда

  • Четыре запроса API: POST /api/batches, POST /api/batches/{batchId}/upload-token, POST /api/batches/{batchId}/complete, DELETE /api/batches/{batchId}.
  • Tus-сервер по протоколу Tus 1.0 с расширениями creation и termination, на том же домене через nginx (443).
  • nginx для Tus-адреса: proxy_request_buffering off, client_max_body_size 0, длинные таймауты.
  • Правильный внешний Location в ответе на создание загрузки.
  • Проверка Tus-запросов по токену и манифесту пакета: batchId, fileIndex, Upload-Length.
  • 401 — на просроченный upload-токен; 404 или 410 на HEAD — только если загрузки действительно нет.
  • Повторный complete безопасен; для постоянных ошибок — 4xx, но не 409 и не 423.
  • Отмена пакета удаляет все его файлы на сервере сама; брошенные пакеты удаляются по сроку хранения.
  • Лимиты: 25 ГиБ на файл, 100 ГиБ на пакет, ГиБ = 1024³ байт.
