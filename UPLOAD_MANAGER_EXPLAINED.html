01Какую задачу решаем

Пользователи загружают через сайт большие данные: фотографии, видео, карты в формате MBTiles и архивы. Один файл весит до 25 ГБ, а за один раз можно загрузить до 100 ГБ. Такая загрузка идёт часами.

За несколько часов обязательно что-нибудь случится: пропадёт Wi-Fi, ноутбук уснёт, сервер перезагрузят. Поэтому главное требование звучит так:

Главное требованиеПосле обрыва загрузка продолжается с того места, где остановилась, а не начинается заново.

Представьте: вы три часа загружали 20 ГБ, на 19-м гигабайте моргнул интернет — и всё сначала. Именно этого мы не допускаем.

02Немного основ: браузер, сервер, запрос

Браузер
Программа у пользователя: Chrome, Firefox, Edge. В нём работает наш сайт — код на TypeScript и React. Это фронтенд, наша часть.
Сервер
Компьютер в дата-центре. Принимает файлы и сохраняет на диск. Это бэкенд, его делает бэкенд-разработчик.

Сообщение браузера серверу, как письмо: «Вот тебе кусок файла» или «Сколько ты уже получил?».
Ответ
Письмо обратно. В нём есть код ответа — число, по которому понятно, как дела.
nginx

03Почему большой файл нельзя просто «отправить»

Обычно файл отправляют одним запросом: «вот весь файл целиком». Для фотографии на 3 МБ это нормально. Для 25 ГБ — плохо: если связь оборвалась посередине, сервер выбрасывает всё полученное, ведь запрос не завершился. Браузеру приходится начинать с нуля.

Аналогия

Вы диктуете по телефону книгу на 500 страниц. На 300-й странице связь прервалась. Если собеседник не записал, где вы остановились, придётся начинать с первой страницы.

04Tus — загрузка «с закладкой»

Tus — это договорённость (по-научному протокол) между браузером и сервером: как загружать файл так, чтобы после обрыва продолжить. Сервер всё время помнит, сколько байт файла уже получил, — как закладку в книге.

  1. Браузер просит создать загрузку (POST). Сервер даёт ей адрес — по нему дальше ищут именно этот файл.
  2. Браузер отправляет содержимое (PATCH). Сервер записывает данные на диск и двигает закладку.
  3. Связь обрывается.
  4. Браузер спрашивает, сколько уже получено (HEAD). Сервер отвечает: 12 ГБ.
  5. Браузер отправляет только остаток.

05Uppy — тележка для файлов

Uppy — готовая библиотека для загрузки файлов в браузере. Мы не пишем всё с нуля, а пользуемся ей.

Один экземпляр Uppy (он создаётся командой new Uppy()) удобно представлять как тележку: в неё складывают файлы, она проверяет правила («не больше 25 ГБ») и знает про каждый файл, загружается ли он, сколько процентов готово и была ли ошибка.

Сама тележка файлы не возит. Для этого к ней подключают плагин — дополнение. У нас это плагин Tus: водитель, который возит по правилам Tus, с закладкой.

const uppy = new Uppy({ ... }); // тележка с правилами
uppy.use(Tus, { ... });         // водитель, который возит по правилам Tus

06Пакет (batch) — посылка из нескольких коробок

Пользователь загружает не один файл, а сразу несколько, и они связаны между собой. Многотомный архив — survey.z01, survey.z02, survey.zip — по частям бесполезен, как отдельные тома энциклопедии. Серия фотографий — это одна съёмка.

К тому же пользователь один раз заполняет метаданные — описание загрузки: тип данных и другие поля формы. Они относятся ко всей загрузке сразу.

Поэтому единица работы у нас — пакет (по-английски batch): посылка из нескольких коробок с одной накладной.

07Черновик — посылку ещё собирают

Пока пользователь заполняет форму и выбирает файлы, посылка ещё не отправлена. Это черновик — как корзина в интернет-магазине до оформления заказа. Черновик — это просто тележка Uppy с файлами, на сервер пока ничего не ушло.

Открыли форму→ Черновик: тележка с файлами→ «Загрузить» — стал пакетом
Черновик→ закрыли форму без отправки — выбросили

Выбросить черновик не страшно: на сервере его нет. А после нажатия «Загрузить» та же самая тележка с теми же файлами становится пакетом (startBatch).

08Зачем нужен UploadManager — диспетчер

Сайт сделан на React. В React интерфейс собирается из компонентов — кирпичиков вроде «форма», «кнопка», «список». Компоненты появляются на экране и исчезают. Модальное окно открыли — компонент появился, закрыли — исчез.

Если хранить загрузку внутри компонента формы, то при закрытии окна она исчезает вместе с ним. Документация Uppy прямо об этом предупреждает. Поэтому загрузками управляет отдельный объект — UploadManager, диспетчер службы доставки.

// Один раз на всё приложение, НЕ внутри компонента:
export const uploadManager = new UploadManager({ tusEndpoint: '/api/uploads/', api });

09Очередь — одна погрузочная рампа

Пользователь может отправить несколько посылок подряд, не дожидаясь первой. По просьбе аналитика они встают в очередь.

Аналогия

На складе одна погрузочная рампа. Грузится одна посылка, остальные ждут. Но саму посылку грузят 4 грузчика сразу — это настройка limit: 4.

Почему не все посылки сразу:

  • интернет-канал у пользователя один и делится между всеми загрузками. Грузить всё сразу — значит закончить всё примерно одновременно, но поздно. По очереди первая посылка придёт раньше, и сервер раньше начнёт её обрабатывать;
  • чем меньше одновременных соединений, тем спокойнее серверу и браузеру.
Правило очередиОдновременно активен только один пакет.

Порядок очереди — порядок, в котором пакеты лежат в поле batches. Это Map — список «ключ → значение», который помнит порядок добавления. За правило отвечает метод startNext(): «если сейчас никто не грузится — возьми первого ожидающего и запусти».

СтатусПо-человеческиАналогия

Кроме статуса у пакета есть флаг ждём повтора (waitingRetry) и текст ошибки (error). Когда пакет загружен и сервер это подтвердил, диспетчер убирает его из списка. Дальше сервер сам распаковывает архивы и копирует данные куда нужно — браузер в этом уже не участвует.

В минимальной версии на этом всё: пакет пропадает из списка. Показывать, чем закончилась обработка на сервере («Обработка», «Готово»), будем позже.

11Ошибки и повторы

Временные

«Сейчас не вышло, но потом получится»: пропал интернет, сервер перезагружается, nginx ответил 502. Повторять имеет смысл.

Постоянные

«Сколько ни повторяй, не поможет»: например, 403 — нет доступа. Нужен человек.

Какая ошибка какая, решает функция isRetryable по коду ответа. Временными считаются: сервер вообще не ответил, 401 (пропуск обновится), 408, 409, 423, 429 и все 5xx.

Повторы — два уровня

Аналогия

Вы звоните в офис, а там занято. Сначала вы сами перезваниваете несколько раз подряд. Не дозвонились — ставите будильник «через 10 секунд» и снова делаете серию звонков. И так, пока не ответят.

  1. Сначала tus перезванивает сам, несколько раз подряд: через 0,1 с, 1 с, 3 с и 5 с. Это встроенная функция плагина, всего около 9 секунд.
  2. Если tus сдался, за дело берётся диспетчер. Он ждёт 10 секунд и запускает новую попытку, которая снова начинается с быстрых повторов tus. Получается цикл примерно по 20 секунд — без ограничения числа попыток. Выключили сервер на час — через час загрузка продолжится сама.

Как ведёт себя очередь при ошибке

  • временная Пакет держит очередь и ждёт. Если пропал интернет, следующий пакет тоже не загрузится, переключаться на него нет смысла.
  • постоянная Пакет переходит в failed и отпускает очередь. Загрузки идут часами, пользователь может отойти, и одна сломанная посылка не должна держать остальные. Тонкость: в failed пакет переходит, только когда ни один его файл уже не загружается, иначе два пакета грузились бы одновременно.
  • Кнопка «Повторить» у пакета с ошибкой ставит его в конец очереди, а не запускает сразу. Правило «один активный пакет» не нарушается.

12Токен — пропуск на склад

Сервер не принимает файлы от кого попало. Каждый запрос несёт токен — электронный пропуск в заголовке: Authorization: Bearer <токен>.

Обычный пропуск пользователя живёт недолго, а загрузка 100 ГБ может длиться дольше. Поэтому сервер выдаёт отдельный пропуск на конкретную посылку — upload-токен. Он действует только для файлов этого пакета, живёт долго и выдаётся запросом issueUploadToken(batchId).

Первый запрос: попросили пропуск→ запомнили→ сервер ответил 401: забыли→ следующий запрос получит новый→ пакет готов или отменён: выбросили

Запоминаем, чтобы не просить пропуск перед каждым из тысяч запросов. Если два запроса попросят его одновременно, оба дождутся одного ответа сервера.

13Главная ловушка: «начать сначала»

Самое хитрое место в коде. После обрыва tus спрашивает сервер «Сколько у тебя есть?» (запрос HEAD). Мы проверили в коде библиотеки и тестом: если на этот вопрос сервер ответил ошибкой (любой, кроме кода 423), tus решает, что старой загрузки больше нет, и начинает файл заново, с нуля.

На ровном месте так бывает, когда сервер перезагружается и nginx отвечает 502, или когда пропуск устарел (401). В обоих случаях закладка на сервере цела, а tus её выбросит.

Аналогия

Вы перезвонили уточнить, на какой странице остановились, а секретарь сказал «Подождите минутку». А tus в этот момент кладёт трубку и начинает диктовать книгу с первой страницы.

Защита — в методе createDraft, в настройке onAfterResponse:

if (req.getMethod() === 'HEAD' && (status === 401 || status >= 500)) {
  throw new Error(`tus: HEAD вернул ${status}`);
}

Мы «выбрасываем ошибку» (throw). Tus воспринимает это как обычный сбой связи и переспрашивает чуть позже, не трогая закладку. Тест показал: без этих трёх строк короткий сбой сервера заставлял файл загружаться заново, а с ними — нет.

14Как UploadManager разговаривает с React

React перерисовывает экран, когда меняются данные. Но UploadManager — обычный объект, и React о нём ничего не знает. Сообщать об изменениях помогает подписка, как на рассылку.

В React для этого есть готовый механизм useSyncExternalStore. Мы завернули его в простой хук:

const batches = useUploadBatches(uploadManager); // список пакетов, всегда свежий

Второй хук — useUploadDraft(uploadManager). При открытии формы он берёт у диспетчера пустую тележку, а при закрытии выбрасывает её, если посылку так и не отправили.

15Весь путь пакета по шагам

  1. Пользователь открывает форму. useUploadDraft получает у диспетчера черновик — пустую тележку.
  2. Перетаскивает файлы. Тележка проверяет формат и размер. Неподходящие файлы не берёт, а пользователь видит причину.
  3. Нажимает «Загрузить». Форма вызывает startBatch(draft, { dataType, metadata }).
  4. Оформление. Диспетчер отправляет на сервер «накладную» — метаданные и список файлов (createBatch). Сервер отвечает номером посылки, batchId.
  5. Подписываем коробки. В каждый файл записываются batchId и fileIndex. Пакет встаёт в очередь queued. Форму уже можно закрыть.
  6. Старт. Если никто не грузится, startNext() запускает пакет uploading.
  7. Загрузка. Перед каждым запросом подставляется пропуск. Файлы летят по 4 одновременно, прогресс идёт в интерфейс.
  8. Пропал интернет. Tus повторяет несколько раз, не выходит, — диспетчер включает автоповтор ждём повтора. В интерфейсе: «Нет связи с сервером. Повторим автоматически».
  9. Интернет вернулся. На очередной попытке tus спрашивает «Сколько у тебя есть?» и докачивает остаток.
  10. Все файлы загружены. Диспетчер сообщает серверу «всё привезли» completing.
  11. Сервер подтвердил. Диспетчер убирает пакет, выбрасывает пропуск и запускает следующий из очереди.

    17Экскурсия по коду UploadManager.ts

    Пройдём файл сверху вниз. Удобно открыть его рядом.

    Поля — что диспетчер помнит

    private readonly batches = new Map<string, Batch>();          // все пакеты в порядке очереди
private readonly submitted = new WeakSet<Uppy>();              // черновики, которые уже отправлены
private readonly tokens = new Map<string, Promise<string>>();  // пропуска по пакетам
private readonly listeners = new Set<() => void>();            // подписчики (компоненты React)
private snapshot: BatchView[] = [];                            // последний снимок для интерфейса
    Map
    Список «ключ → значение». Ключ — номер посылки, batchId.
    WeakSet
    Набор объектов, который не мешает браузеру освободить память. Отличает «черновик ещё в форме» от «черновик уже отправлен».
    Promise<string>
    «Обещание строки»: пропуск может ещё быть в пути с сервера. Два запроса, попросившие его одновременно, дождутся одного ответа.

    Методы

    constructor
    Вешает обработчик beforeunload: если закрыть вкладку при незавершённых загрузках, браузер спросит «Точно уйти?».
    createDraft
    Создаёт тележку с правилами: лимиты 25 и 100 ГБ, проверка формата и дублей, плагин Tus с пропуском в каждом запросе, повтором при 401 и защитой из раздела 13.
    discardDraft
    Выбрасывает тележку, если её ещё не отправили. Отправленную не трогает — это уже пакет.
    startBatch
    Оформляет посылку. Черновик помечается как отправленный до запроса к серверу, поэтому закрытие формы во время ожидания его не уничтожит. Здесь же диспетчер подписывается на события тележки: progress, upload-success, upload-error.
    startNext
    Есть активный пакет — ждём. Нет — берём первый queued и запускаем.
    run
    Запускает или продолжает пакет. Все файлы уже загружены — сразу complete. Иначе uppy.upload(): Uppy сам перезапустит файлы с ошибкой и начнёт ещё не начатые.
    complete
    Сообщает серверу «всё привезли». Получилось — убираем пакет, выбрасываем пропуск, запускаем следующий. Нет — handleError.
    handleError
    Временная ошибка — таймер на 10 секунд (один на пакет). Постоянная — запоминаем текст и отменяем таймер.
    failIfStuck
    Есть постоянная ошибка и ни один файл уже не грузится? Пакет переходит в failed, запускается следующий.
    retryBatchNow
    Кнопка «Повторить». Пакет в очереди — ничего. Пакет в failed — в конец очереди. Активный — повтор сразу. Этот же метод вызывает таймер автоповтора.
    cancelBatch
    Кнопка «Отменить»: убрать пакет (Uppy остановит загрузку и попросит сервер удалить недогруженное), запустить следующий, сообщить серверу, выбросить пропуск.
    getUploadToken
    Отдаёт пропуск: из памяти или, если его нет, просит у сервера.
    Помощники
    remove — убрать пакет; clearRetry — отменить таймер; notify — сделать снимок и сообщить подписчикам; toView — данные пакета для интерфейса; isRetryable — временная ли ошибка.

    19Как этим пользоваться

    Подключить

    // 1. Один раз на всё приложение — у нас это src/services/Uploader.ts.
//    Остальные файлы делают import { uploadManager } from '…/services/Uploader'.
//    http — HTTP-клиент приложения;
//    при ошибке он должен выбрасывать ошибку с полем status.
export const uploadManager = new UploadManager({
  tusEndpoint: '/api/uploads/', // точный путь даст бэкенд
  api: {
    createBatch: (input) => http.post('/api/batches', input),
    issueUploadToken: (batchId) =>
      http.post(`/api/batches/${batchId}/upload-token`).then((response) => response.token),
    completeBatch: (batchId) => http.post(`/api/batches/${batchId}/complete`),
    cancelBatch: (batchId) => http.delete(`/api/batches/${batchId}`),
  },
});

// 2. В модальном окне — форма. После отправки окно закрываем.
<UploadForm manager={uploadManager} onSubmitted={closeModal} />

// 3. Где-нибудь на странице — список текущих загрузок.
<BatchList manager={uploadManager} />

    Частые изменения

    НужноГде
    Поменять лимитыfileRules.ts: MAX_FILE_SIZE, MAX_BATCH_SIZE. И сказать бэкенду — у него те же лимиты
    Добавить форматfileRules.ts: массив ALLOWED_NAME_PATTERNS
    Сколько файлов грузить сразуUploadManager.ts, createDraft: настройка limit
    Пауза перед автоповторомUploadManager.ts: RETRY_INTERVAL
    Чего делать нельзя
    • Создавать UploadManager внутри компонента — загрузка будет пропадать вместе с компонентом.
    • Вызывать uppy.destroy() у пакета «просто так», например при закрытии окна, — это остановит загрузку и удалит недогруженные файлы на сервере.
    • Убирать защиту HEAD в onAfterResponse — вернётся «начать сначала».
    • Класть сами файлы (File) в состояние формы или в localStorage — они огромные и живут только в тележке Uppy.

    20Почему решения именно такие

    РешениеПочему
    Протокол TusДаёт продолжение с места остановки — главное требование
    Библиотека UppyПроверки файлов, прогресс, повторы и работа с Tus уже готовы и проверены
    Диспетчер вне компонентовЗакрытие окна не должно обрывать загрузку
    Пакет вместо файловТома архива и метаданные — одно целое
    Тележка на каждый пакетПакеты не путаются, лимит 100 ГБ считается на пакет, отмена одного не трогает другие
    Очередь пакетовПросьба аналитика; первая посылка приходит раньше; меньше нагрузка
    Свой автоповторВстроенные повторы tus сдаются примерно за 9 секунд, а продолжить нужно, когда сервер вернётся, — хоть через час
    Отдельный пропускЗагрузка может длиться дольше, чем живёт обычный пропуск пользователя
    Защита HEADБез неё короткий сбой сервера заставлял загружать файл с нуля (проверено тестом)
    Файл целиком, без кусковТак советует документация Uppy и tus: куски нужны, только если сервер ограничивает размер запроса. При обрыве сервер сохраняет всё, что успел получить, если nginx настроен, как договорились с бэкендом
    Без localStorageПродолжение после закрытия вкладки пока не требуется, а старые записи только мешали бы

    21Что будет, если…

    СитуацияЧто произойдёт
    Закрыли окно во время загрузкигрузится Загрузка продолжается, её видно в списке загрузок
    Закрыли окно во время отправки формыв очереди Загрузка всё равно начнётся
    Пропал интернет на минутуждём повтора «Нет связи с сервером. Повторим автоматически». Связь вернулась — продолжение с того же места
    Сервер перезагрузилиждём повтора То же самое
    Устарел пропускгрузится Диспетчер незаметно получает новый и продолжает
    Сервер ответил «нет доступа»ошибка Следующие пакеты загружаются дальше. Можно нажать «Повторить» или «Отменить»
    Нажали «Отменить»Загрузка останавливается, данные на сервере удаляются, стартует следующий пакет
    Закрыли вкладку браузераБраузер спросит «Точно уйти?». Если уйти, загрузка прервётся: продолжение после закрытия вкладки пока не сделано
    Отправили второй пакет, пока грузится первыйв очереди Второй ждёт и стартует сам
    Пакет загрузилсяСервер подтвердил — пакет пропадает из списка текущих загрузок
    Бросили файл мимо зоны, пока открыта формаНичего: браузер не откроет файл и не уйдёт со страницы

    22Словарик

    Браузер
    Программа, в которой открыт сайт
    Сервер
    Удалённый компьютер, который принимает файлы
    Фронтенд / бэкенд
    Код в браузере (наш) / код на сервере
    Запрос / ответ
    Сообщение браузера серверу и ответ сервера
    Код ответа
    Число в ответе: 200 — хорошо, 401 — нужен новый пропуск, 403 — нельзя, 5xx — сбой сервера
    API
    Набор запросов, которые понимает сервер
    Токен
    Электронный пропуск, который прикладывается к запросу
    Tus
    Правила загрузки «с закладкой»
    Смещение (offset)
    «Закладка»: сколько байт файла сервер уже получил
    Uppy
    Библиотека загрузки файлов; один её экземпляр — «тележка» с файлами
    Плагин
    Дополнение к Uppy; плагин Tus возит файлы по правилам Tus
    Пакет (batch)
    Одна загрузка: несколько файлов плюс метаданные
    Метаданные
    Описание загрузки: тип данных и другие поля формы
    Черновик
    Пакет до нажатия «Загрузить»
    Очередь
    Порядок, в котором загружаются пакеты
    Событие
    Сообщение, которое Uppy присылает сам: «файл загружен», «ошибка»
    Компонент
    Кусочек интерфейса на React: форма, кнопка, список
    Хук
    Функция React, которая подключает компонент к данным
    Монтирование
    Компонент появился на экране; размонтирование — исчез
    Promise, async/await
    Способ работать с тем, что придёт не сразу, например с ответом сервера
    Снимок (snapshot)
    «Фотография» состояния загрузок для интерфейса
