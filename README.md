# Загрузка больших файлов с докачкой (Uppy + Tus)

Фронтенд загрузки файлов пакетами: если связь оборвалась, загрузка продолжается с того места, где остановилась. React, TypeScript, react-hook-form, Uppy 6, протокол Tus.

Настоящего бэкенда пока нет, поэтому в проекте есть заглушка бэкенда и страница, на которой всё можно проверить локально.

## Что где лежит

| Путь | Что это |
|---|---|
| `src/upload/` | Код загрузки: менеджер загрузок, компоненты, типы. Переносится в основное приложение |
| `src/services/Uploader.ts` | Единственный менеджер загрузок на всё приложение и запросы к API. Компоненты импортируют `uploadManager` отсюда. В основном приложении `fetch` здесь заменяется на его HTTP-клиент |
| `dev/mock-server.mjs` | Заглушка бэкенда: четыре запроса API и настоящий Tus-сервер |
| `dev/main.tsx` | Страница для проверки: форма и список загрузок |
| `UPPY_UPLOAD_IMPLEMENTATION.md` | Спецификация: требования, решения, контракт API |
| `UPLOAD_API_FLOW.html` | Все запросы по шагам — для бэкендера |
| `UPLOAD_MANAGER_EXPLAINED.md` / `.html` | Как всё устроено, простым языком |

`dev/`, `package.json` и `vite.config.ts` нужны только для локальной проверки, в приложение их не переносим.

## Как запустить

Нужен Node.js 20.19 или новее.

```bash
npm install
```

Дальше — два терминала в папке проекта.

**Терминал 1 — заглушка бэкенда:**

```bash
npm run mock
```

**Терминал 2 — страница:**

```bash
npm run dev
```

Откройте http://localhost:5174.

В терминале заглушки видно каждый запрос, например:

```text
POST    /api/batches → 201
POST    /api/batches/e29cb10c/upload-token → 200
        файл №0 пакета e29cb10c: flight_0412.mp4
POST    /api/uploads/ → 201
PATCH   /api/uploads/1b1d43aa… → оборван  (с байта 0)
HEAD    /api/uploads/1b1d43aa… → 200
PATCH   /api/uploads/1b1d43aa… → 204  (с байта 15793393)
POST    /api/batches/e29cb10c/complete → 202
```

Загруженные файлы складываются в `dev/.data/uploads`. Чтобы начать с чистого листа, остановите заглушку и удалите папку `dev/.data`.

### Настройки заглушки

| Переменная | По умолчанию | Что меняет |
|---|---|---|
| `SPEED_MB` | `10` | Скорость приёма одного файла, МБ/с. Локально всё грузится мгновенно, а так видно прогресс и можно успеть оборвать загрузку |
| `TOKEN_TTL` | `600` | Сколько секунд живёт upload-токен |

Пример: `SPEED_MB=2 TOKEN_TTL=30 npm run mock`.

### Порты

| Что | Адрес |
|---|---|
| Страница | http://localhost:5174 |
| Заглушка бэкенда | http://localhost:3101 |

Страница отправляет запросы `/api` на заглушку через Vite, как в настоящем приложении через nginx. Порты заданы в `vite.config.ts` и `dev/mock-server.mjs`.

## Что попробовать

| Сценарий | Как сделать | Что должно быть |
|---|---|---|
| Обычная загрузка | Выбрать файлы, нажать «Загрузить» | Полоска прогресса, потом пакет пропадает из списка |
| Сервер недоступен | Во время загрузки нажать Ctrl+C в терминале заглушки, подождать, снова `npm run mock` | «Нет связи с сервером. Повторим автоматически», потом загрузка продолжается с того же места |
| Пропал интернет | DevTools → Network → Offline, потом Online | То же |
| Очередь | Отправить второй пакет, пока грузится первый | Второй — «В очереди», стартует сам после первого |
| Закрыть форму | Нажать «Закрыть форму» во время загрузки | Загрузка продолжается |
| Отмена | «Отменить» и подтвердить | Пакет пропадает, файлы удаляются из `dev/.data/uploads` |
| Закрыть вкладку | Обновить страницу во время загрузки | Браузер спрашивает «Покинуть сайт?» |
| Истёк upload-токен | `TOKEN_TTL=30 npm run mock`, оборвать загрузку больше чем через 30 с | В логе 401, новый токен, загрузка продолжается |
| Неподходящий файл | Выбрать, например, `.txt` | «не добавлен: такой формат не поддерживается» |
